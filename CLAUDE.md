# GA Forum (ga-forum.com): standing rules

Independent software research site plus a forum, for game developers, streamers, esports organizers and corporate live-video teams. Global (no European-ownership rule), American English on every page. Published by G-Cas B.V. (Utrecht); editor Sebastiaan Smits. Lead mail and the wider workflow live in ~/Documents/europeanpurpose/CLAUDE.md. Repo: https://github.com/narrinai/gaforum (branch main). Netlify and DNS are set up by the owner.

## Before any page work, read
- data/CATEGORY_BRIEF.md (ranking file contract, rules, overlap gate)
- data/CONTENT_BRIEF.md (alternatives, comparisons, guides, research, news, glossary, forum seed threads)

## Hard rules
- Every HTML page is generated by `scripts/build.py` from `data/`. Edit data or the build script, never the HTML.
- Facts only from pages actually opened: vendor facts live in `data/facts/*.json` (merged into `data/facts/index.json` by `scripts/merge_facts.py`), each with the URL it came from. Research figures only from opened pages, each linked. No figures from search snippets or memory. No "we tested".
- Only tools with `status: "verified"` may be ranked. A ranking needs at least 10 verified tools WITH a real logo in `images/tools/<slug>.(png|svg)`; the build leaves out tools without a logo and holds the page below 10 (it prints HELD). Never ship monograms or placeholder logos; drop the tool instead.
- No tool pages (/tool/) for now. Ranking entries link to the vendor with rel="nofollow noopener".
- Disclosure line, verbatim, above every ranking: "Vendors can pay for more visibility; how that works is explained in our disclosure, linked above every ranking. No commission is earned on clicks or purchases, and we do not work as an affiliate." Never say placements are labeled or tagged.
- No em dashes anywhere. Never write "top 10". No hype words, no exclamation marks.
- Never name Lattice, Leapsome, Dialog, Welder, Learned, Flip, Staffbase, Blink, Beekeeper or Microsoft Viva on a page that names Treams or Speakap (the validator blocks these names in rankings).
- Overlap gate: pages of the same type share at most 15% of their 6-word sequences (`python3 scripts/check_overlap.py --all`). Vary the fixed sentence frames per page; rewrite rather than cut. Also keep pages clearly different from the sister sites' similar pages (TKE, TI, ATC): the planning file listed those pairs; never open sister pages for wording.
- Every ranking links to its own forum thread (/forum/t/<category-slug>, generated automatically as a seed thread).
- The history page states facts about Gaming-Age Forums / NeoGAF only from archive.org captures, linked per fact, and says GA Forum is not connected to those communities. Never copy old forum posts.

## Build and checks (all must pass before a commit)
```
python3 scripts/merge_facts.py          # after adding data/facts/*.json
python3 scripts/build.py                # writes pages, sitemap, llms.txt, llms-full.txt, _redirects, forum shell + seed
python3 scripts/validate_categories.py  # every ranking OK
python3 scripts/check_overlap.py --all  # every type under 15%
python3 scripts/check_links.py          # 0 broken, 0 orphans
npm run test:forum                      # forum unit/render tests (offline harness)
```
Local preview: `python3 scripts/serve.py` (static only) or `netlify dev --offline` (functions, Blobs sandbox, _redirects incl. query rules).
Push yourself after the gates pass; never push a failed build.

## Adding pages
- Ranking: add `data/categories/<slug>.json` (brief), facts in `data/facts/extra_<slug>.json`, logos in `images/tools/` (`python3 scripts/fetch_logos.py` fetches apple-touch-icon/manifest icons; look at every logo before keeping it), build, gates.
- Alternatives / comparison / guide / research / news: JSON in the matching data folder (CONTENT_BRIEF.md), build, gates.
- Forum starter thread: `data/forum/threads/<id>.json` (author is always the editorial team; no fake user replies).
- Glossary: `data/glossary.json`.

## Forum (Netlify Functions + Netlify Blobs)
- `netlify/functions/forum-page.mjs` server-renders /forum, /forum/<board>, /forum/t/<id>, /forum/admin, /forum/account inside the site chrome from `netlify/functions/lib/shell.mjs` (generated by the build). Seed threads come from `netlify/functions/lib/forum-seed.json` (generated). API: `netlify/functions/forum-api.mjs` at /api/forum/*. Client: js/forum.js, css/forum.css. Docs: netlify/functions/lib/forum/README.md.
- Env vars: SENDGRID_API_KEY (login codes and form auto-replies; without it login shows "temporarily unavailable"), SESSION_SECRET (cookie signing; falls back to a random secret stored in Blobs), ADMIN_EMAILS (comma list; default hello@ga-forum.com).
- Moderation: posts with links from accounts younger than 3 days or with fewer than 3 approved posts are held; 3 reports hide a post; admins review at /forum/admin.

## Old URLs
`data/legacy-redirects.txt` (vBulletin forumdisplay/showthread/archive, member and WordPress leftovers) is written into `_redirects` by the build: forum sections and threads 301 to /software/games, /software or /history; member/posting/spam URLs answer 404. Do not add a `/forum/*` catch-all: /forum is the new forum.

## Forms
Netlify forms `get-listed` and `contact` (honeypot `bot-field`, action /thanks). `netlify/functions/submission-created.mjs` schedules an auto-reply through SendGrid from hello@ga-forum.com (optional EP_INGEST_KEY sends the lead to the shared tracker as site "gaf").

## Scope of site-level copy (Seb, 18 Nov 2026)
GA Forum will expand beyond gaming. Site-level meta (homepage title/description, data/site.json tagline and description, /software, /about, /guides, WebSite/Organization schema) stays category-neutral ("software reviews, comparisons and forum"); gaming is named only as the current first focus. Category pages and hubs stay specific. Main nav label for /software is "Software Reviews".

## Overview pages stay short (Seb, 18 Nov 2026)
/software shows at most 8 rankings per hub with an "All <hub> rankings (N)" link; the hub page lists all. When a hub passes ~40 rankings, split it into sub-hubs (each with its own unique intro) rather than growing one long list. Same for /alternatives, /compare and /glossary once they pass ~100 entries.
